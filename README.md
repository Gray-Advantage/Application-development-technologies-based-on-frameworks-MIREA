# Сервис сокращения ссылок

Сервис сокращения длинных URL-адресов с учётом переходов и контролем срока
действия ссылок. Консольное приложение с объектной моделью (ПР1–ПР3)
дополнено веб-интерфейсом на Django (ПР5).

## Назначение

Приложение предназначено для сокращения длинных URL-адресов: пользователь
передаёт сервису длинную ссылку и получает короткий адрес, которым удобно
делиться в мессенджерах, социальных сетях и печатных материалах.
Дополнительно сервис ведёт учёт переходов по созданным ссылкам и
контролирует срок их действия.

Приложение решает три задачи:

- длинные адреса неудобно пересылать и размещать;
- владельцу ссылки нужна статистика переходов по ней;
- часть ссылок должна быть доступна ограниченное время.

## Целевая аудитория

- SMM-специалисты и авторы контента, размещающие ссылки в постах и рассылках;
- маркетологи, которым нужна статистика переходов по рекламным материалам;
- преподаватели и организаторы мероприятий, публикующие ссылки на материалы;
- обычные пользователи, которым нужно передать длинный адрес в переписке.

## Предметная область

Предметная область — сокращение и учёт веб-ссылок. Пользователь создаёт
короткие ссылки. Короткая ссылка состоит из домена сервиса и короткого кода,
который генерируется автоматически или задаётся вручную. У ссылки есть
владелец, дата создания и срок действия. Каждый переход по короткой ссылке
фиксируется и используется для формирования статистики.

Правила предметной области:

- короткий код уникален: занятый код повторно использовать нельзя;
- перейти можно только по включённой ссылке, срок действия которой не истёк;
- отключённая ссылка остаётся в сервисе вместе со статистикой переходов,
  но новые переходы по ней невозможны;
- логин и адрес электронной почты пользователя уникальны.

## Основные сущности

| Сущность     | Класс   | Назначение                                        |
|--------------|---------|---------------------------------------------------|
| Пользователь | `User`  | владелец коротких ссылок                          |
| Ссылка       | `Link`  | короткая ссылка на исходный адрес                 |
| Переход      | `Click` | факт открытия короткой ссылки                     |
| Тег          | —       | группировка ссылок, появится позже                |

### User — пользователь

Атрибуты: `id`, `username`, `email`, `registered_at`.

Методы: `__str__()`; `validate_email()` — статический метод; `from_data()` —
метод класса, создающий объект из записи JSON.

### Link — короткая ссылка

Атрибуты: `code`, `url`, `owner` (объект `User`), `created_at`,
`expires_at`, `is_active`; свойство `short_url` (`@property`).

Методы: `days_left()`, `days_passed()`, `is_available()`, `get_state()`,
`deactivate()`, `__str__()`; `validate_url()` и `validate_code()` —
статические методы.

### Click — переход по ссылке

Атрибуты: `id`, `link` (объект `Link`), `clicked_at`, `source`.

Методы: `__str__()`.

## Взаимодействие объектов

Объекты связаны композицией: переход хранит объект ссылки, а ссылка —
объект своего владельца.

```text
Click
 └── link ──→ Link
               └── owner ──→ User
```

Поэтому данные связанных объектов доступны напрямую: `click.link.short_url`,
`link.owner.username`, `click.link.owner.email`.

Приложение работает с коллекциями объектов `list[User]`, `list[Link]` и
`list[Click]`. Операции над конкретным объектом реализованы его методами
(`link.deactivate()`, `link.is_available(today)`), а операции над
коллекциями — функциями модулей (`add_link()`, `find_links()`,
`register_click()`, `get_top_links()`).

## Веб-интерфейс

Веб-часть приложения реализована на Django. Реализованные страницы:

| Страница          | URL                        | View-функция                  | Назначение                              |
|-------------------|----------------------------|-------------------------------|-----------------------------------------|
| Главная           | `/`                        | `homepage.views.index()`      | описание сервиса и навигация            |
| Список ссылок     | `/links/`                  | `links.views.links()`         | объекты `Link` из `data/links.json`     |
| Страница ссылки   | `/links/<slug:code>/`      | `links.views.link_detail()`   | карточка ссылки и её статистика         |
| Список переходов  | `/clicks/`                 | `clicks.views.clicks()`       | объекты `Click` из `data/clicks.json`   |
| Страница перехода | `/clicks/<int:click_id>/`  | `clicks.views.click_detail()` | карточка перехода и связанная ссылка    |

Если ссылки с указанным кодом или перехода с указанным идентификатором нет,
страница возвращается с кодом статуса 404. Для адресов, которым не нашлось
маршрута, подключён собственный обработчик `handler404`
(`homepage.views.page_not_found()`); он виден при `DEBUG = False`.

Маршрутизация двухуровневая: корневой `shortener/urls.py` распределяет адреса
между приложениями через `include()`, а конкретные адреса описаны в
`homepage/urls.py`, `links/urls.py` и `clicks/urls.py`. В адресах
используются конвертеры путей: `<slug:code>` для короткого кода ссылки и
`<int:click_id>` для номера перехода.

Общий HTML-каркас страниц (кодировка, метатег `viewport`, подключение
Bootstrap 5.3 через CDN и навигация) собирает функция `page()` из
`homepage/views.py`: view-функции передают в неё заголовок вкладки и
содержимое страницы. Оформление построено на классах Bootstrap: `nav`,
`container`, `list-group`, `card`, `badge`, `btn`, `display-4`, `lead`.

### Доступно только в консольной версии

Операции, изменяющие данные, появятся в веб-интерфейсе после изучения форм
и POST-запросов:

- создание короткой ссылки;
- регистрация перехода;
- отключение ссылки;
- добавление и поиск пользователей.

## Основные функции

1. **Создание короткой ссылки** — владелец выбирается по ID, код генерируется
   из MD5-хеша исходного адреса или задаётся вручную; адрес, код и срок
   действия проверяются перед созданием.
2. **Проверка занятости короткого кода** — контроль формата и уникальности
   кода.
3. **Проверка срока действия ссылки** — определение состояния ссылки и
   просмотр только доступных ссылок.
4. **Учёт переходов и статистика** — регистрация перехода с датой и
   источником, статистика по ссылке и общая статистика сервиса с рейтингом
   ссылок.
5. **Просмотр сведений о ссылках** — список с сортировкой и поиск по части
   кода или адреса; в веб-интерфейсе — список ссылок и карточка ссылки.
6. **Отключение ссылки** — ссылка перестаёт принимать переходы, статистика
   сохраняется.
7. **Работа с пользователями** — добавление, просмотр, поиск и просмотр
   ссылок пользователя.

## Хранение данных

JSON используется для хранения данных, а объекты — для работы приложения.
При загрузке записи JSON превращаются в объекты, при сохранении — обратно в
записи. Связанные объекты в файлах заменяются идентификаторами: владелец
ссылки хранится как `owner_id`, ссылка перехода — как её короткий код `code`.
Данные загружает функция `load_all()` модуля `storage.py`; её используют и
консольная версия, и view-функции Django.

`data/users.json`:

```json
[
    {
        "id": 1,
        "username": "ivan_petrov",
        "email": "ivan@example.com",
        "registered_at": "2026-07-15"
    }
]
```

`data/links.json`:

```json
[
    {
        "code": "mirea",
        "url": "https://www.mirea.ru/education/programmy-obucheniya/",
        "owner_id": 2,
        "created_at": "2026-09-01",
        "expires_at": "2026-10-01",
        "is_active": true
    }
]
```

`data/clicks.json`:

```json
[
    {
        "id": 1,
        "code": "py-docs",
        "clicked_at": "2026-08-03",
        "source": "direct"
    }
]
```

Даты хранятся в формате ГГГГ-ММ-ДД. Django ORM и база данных приложения пока
не используются: файл `db.sqlite3` создаётся только для служебных таблиц
Django.

## Тестирование

```bash
pytest -v
```

Тесты проверяют создание объектов `User`, `Link` и `Click`, их атрибуты и
строковое представление, методы классов, поиск, фильтрацию и сортировку,
связи между объектами, правила предметной области и статистику переходов.

## Проверка качества кода

Код проверяется двумя линтерами с одинаковыми настройками: flake8
(настройки в `setup.cfg`) и ruff (настройки в `pyproject.toml`). Для обоих
задана длина строки 88 символов, одинаковый набор проверок pycodestyle и
pyflakes и проверка кавычек: во всём коде используются двойные кавычки.
Аннотации типов проверяются mypy (настройки в `pyproject.toml`).

```bash
flake8
```

```bash
ruff check
```

```bash
mypy
```

```bash
python manage.py check
```
